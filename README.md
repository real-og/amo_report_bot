# Отчёты по сделкам amoCRM

Скрипт получает сделки через API v4 amoCRM и создаёт отдельный Excel-файл для каждой из трёх настроенных воронок. Сделки группируются по месяцу создания, затем идут по заданному порядку этапов. Успешные сделки идут предпоследними и выделяются светло-зелёным, нереализованные — последними и выделяются розовым.

## Что попадает в отчёт

- воронки `РЕКЛАМА НА ТРАНСПОРТЕ`, `БРЕНДИРОВАНИЕ АВТО`, `РЕКЛАМА В ЧЕХЛАХ`;
- сделки, созданные начиная с `date_from` и до `date_to` включительно;
- шесть рабочих этапов из `included_status_names`, строго в указанном там порядке;
- успешные и нереализованные сделки;
- 10 столбцов из задания: название, этап, контакт, ответственный, город, услуга, сумма, источник, примечания и причина нереализации.

## Установка

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows
pip install -r requirements.txt
cp .env.example .env
cp config.example.json config.json
```

## Настройка интеграции amoCRM

Заполните `.env` данными amoCRM:

- `AMOCRM_SUBDOMAIN` — часть адреса до `.amocrm.ru`;
- `AMOCRM_ACCESS_TOKEN` — ваш долгосрочный токен.

Обновление токена не выполняется. Если amoCRM вернёт `401`, скрипт сообщит, что токен нужно проверить.

## Настройка отчёта

В `config.json`:

- `date_from` — начало периода, например `2026-08-01`;
- `date_to` — конец периода или `null`, чтобы выгружать по текущий момент;
- `pipelines` — ID или точные названия трёх нужных воронок;
- `included_status_names` — рабочие этапы и их порядок в отчёте;
- `custom_fields` — соответствие столбцов пользовательским полям amoCRM.

Для полей надёжнее указать числовой `id`. Если `id` равен `null`, скрипт ищет поле по `name`. ID поля виден в ответе `GET /api/v4/leads/custom_fields` или в инструментах разработчика браузера.

Настроенные воронки:

```json
"pipelines": [
  "РЕКЛАМА НА ТРАНСПОРТЕ",
  "БРЕНДИРОВАНИЕ АВТО",
  "РЕКЛАМА В ЧЕХЛАХ"
]
```

Если «Примечания» в вашей amoCRM — не пользовательское поле сделки, а системная лента заметок, потребуется отдельная загрузка `/api/v4/leads/{id}/notes`. Текущая версия считает «Примечания» пользовательским полем, чтобы не выполнять отдельный запрос для каждой сделки.

## Запуск

Из папки проекта:

```bash
python amocrm_report.py
```

Или с другими файлами настроек:

```bash
python amocrm_report.py --config config.json --env .env
```

Готовые файлы появятся в папке `reports`. Название каждого файла совпадает с названием воронки.

## Важное правило периода

Сейчас месяц определяется по `created_at` — дате создания сделки. Если вам нужна разбивка по дате перехода сделки в этап или по дате закрытия, алгоритм нужно изменить: история переходов загружается отдельно через события amoCRM.
